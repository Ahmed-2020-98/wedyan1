# وديان — منصة بيع وحجز اللوحات الفنية

معرض إلكتروني لفنانة تبيع لوحاتها. نوعان من المعروضات: **لوحة جاهزة** تُشترى
وتُشحن مباشرةً، و**لوحة تُحجز** لتُرسم خصيصاً للزبون وفق مقاس ووصف يختارهما.

---

## الفكرة في سطرين

> المنصة ليست متجراً يبيع قطعاً متطابقة، بل معرضاً لأعمال فريدة. لذلك كل لوحة
> جاهزة كمّيتها واحدة وتنتقل إلى «مباعة» لا إلى «نفدت الكمية».
>
> والحجز ليس طلباً مؤجّلاً بل مسار إنتاج له حالاته الخاصة: يراجعه الفنان
> ويُسعّره، ثم يُدفع عربون، ثم تُحدَّث مراحل الرسم بالصور حتى الاكتمال، ثم
> يُسدَّد المتبقّي ويبدأ الشحن.

## جرّبها في ثلاث دقائق

```bash
# ١) الخادم وقاعدة البيانات
cd backend
composer install
cp .env.example .env && php artisan key:generate
# اضبط DB_PORT حسب خادم MySQL لديك (8889 لـ MAMP، 3306 لـ Homebrew)
php artisan migrate:fresh --seed
php artisan storage:link
php artisan serve --port=8300

# ٢) المتجر (تصيير على الخادم)
cd ../web && npm install && npm start -- --port 4200

# ٣) لوحة التحكم
cd ../admin && npm install && npm start -- --port 4300

# ٤) عامل الطوابير — بدونه لا تصل الإشعارات
cd ../backend && php artisan queue:work
```

ثم افتح <http://localhost:4200>.

> بذر البيانات يستغرق دقيقة ونصف: يولّد ٢٤ لوحة تجريدية بـGD مع نسخ WebP
> لكل منها. منصة لبيع اللوحات تبدو مكسورة تماماً بصور بديلة رمادية.

**حسابات العرض** — كلمة المرور `password` للجميع:

| الحساب | الدور | أين |
|--------|-------|-----|
| `customer@wedyan.local` | زبون | المتجر `:4200` |
| `artist@wedyan.local` | الفنانة | اللوحة `:4300` |
| `admin@wedyan.local` | مدير | اللوحة `:4300` |

> بوابة الدفع تعمل بسائق `fake` افتراضياً، فيكتمل مسار الشراء والحجز كاملاً
> **بلا أي حساب لدى مزوّد الدفع**. صفحة المحاكاة تمرّ بنفس مسار الخطّاف الذي
> يسلكه مزوّد حقيقي، فما تختبره هو المنطق نفسه لا اختصاراً له.

### جرّب المسارين

**الشراء:** سجّل حساباً → اختر لوحة «جاهزة» → اشترِ الآن → أكمل العنوان →
اختر الشحن → ادفع (زر «إتمام الدفع بنجاح») → تابع الطلب من `حسابي ← طلباتي`.

**الحجز:** اختر لوحة «قابلة للحجز» → اطلب هذه اللوحة → صف ما تريد → أرسل.
ثم من `:4300` بحساب الفنانة: اقبل وحدّد السعر. عد إلى المتجر وادفع العربون،
فتتحوّل الحالة إلى «قيد التنفيذ». أضف تحديث مرحلة من لوحة الفنانة، ثم «اكتملت
اللوحة»، ثم ادفع المتبقّي — تصبح «جاهزة للتسليم».

## البنية

```
code1-artist-ecommerce/
├── backend/     Laravel 13 — الواجهة البرمجية ومنطق الأعمال والدفع
├── web/         Angular 22 + SSR — المتجر ولوحة الزبون
├── admin/       Angular 22 — لوحة الفنانة والإدارة (مقسّمة بالأدوار)
└── docs/        التوثيق
```

**لماذا تطبيقان لا أربعة؟** لوحة الزبون تشارك المتجر الجلسة والسلة والترويسة
ونظام التصميم، فوضعها داخل `web` خلف حارس مسار أوفر من تطبيق مستقل. ولوحتا
الفنانة والإدارة تتشاركان الجداول والرسوم والتخطيط ولا تختلفان إلا في
الصلاحيات، فجُمعتا في `admin` وفُصلتا بحارس أدوار.

**التصيير على الخادم في `web` فقط، ولصفحاته العامة وحدها.** صفحات اللوحات
يجب أن تُفهرس وأن تظهر معاينتها عند المشاركة؛ أما السلة والحساب والدفع فتُصيَّر
في المتصفح — رمز الدخول يعيش في `localStorage` ولا وجود له على الخادم.

## الاختبارات

```bash
cd backend && php artisan test     # على MySQL لا sqlite — انظر phpunit.xml
cd web && npm test
cd admin && npm test
```

اختبارات الخادم تعمل على MySQL عمداً: ضمان «اللوحة تُباع مرّة واحدة» يقوم على
قيود المفاتيح الأجنبية وقفل الصفوف، وsqlite لا يحاكي أيّاً منهما.
